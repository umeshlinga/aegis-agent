# Tools and Models Inventory

Every tool, model, library, and data source the Aegis v2 product uses
or will use, in one table per group. Each row says what the piece
does here, why it was chosen, what was rejected and why, and whether
it needs a key or costs money.

Status words are used strictly:

- **IN USE NOW** means the code is in this repo and exercised by the
  test suite or a harness run today.
- **PLANNED FOR V2** means the piece is named in PRODUCT_PLAN.md as
  part of a phase that has not run yet. Nothing planned is described
  as working, and no result depends on a planned piece.

## Agent framework and runtime pieces

| Name | What it does here | Why chosen | Rejected, and why | Key / cost | Status |
| --- | --- | --- | --- | --- | --- |
| Aegis agent core (own implementation, LangGraph style pattern) | The checkpointed state machine at the centre: plan, act, verify, recover, done, failed, with a checkpoint after every verified step | The states, transitions, and checkpoint contract needed to be visible in the trace and owned by this project from day one; the pattern (explicit states, transitions as data, durable checkpoints) follows the LangGraph style of graph based agent design, implemented directly so nothing about the core loop is hidden inside a library | Starting on a graph library (LangGraph itself) was considered on Day 1 and deferred, not dismissed: if the core loop was wrong, no framework would save it. The runner interface is shaped so a graph library can be bound later behind the same contract, and that remains an open option, recorded here so nobody claims LangGraph is imported when it is not. It is not imported today | No key, no cost | IN USE NOW |
| Permissioned tool registry (own code) | Declares every tool with a permission scope (read, write, act, spend), a run policy, and an irreversibility flag; enforces approval gates in code | Safety rules that live in prompts are suggestions; rules that live in the registry run every time, and the recovery engine treats a denial as final | Prompt level guardrails as the main mechanism were rejected for the reason in the previous column; they can exist as well, never instead | No key, no cost | IN USE NOW |
| Recovery engine (own code) | Classifies failures into a taxonomy and answers with a changed strategy retry, a rollback to the last verified checkpoint, or an honest abort; has the on/off ablation switch the eval harness measures with | Recovery is the product's measured claim, so it had to be explicit, classifiable, and switchable, not an emergent behaviour of a framework | Blind retry (repeat the identical call) was rejected: it is the failure mode this project exists to beat | No key, no cost | IN USE NOW |
| Trace store and trace explorer (own code) | Append only JSONL event record of every run, and the read only web UI that renders a run as a timeline with recovery events and gate refusals highlighted | Traces are the single source of truth for results; a file format any tool can read beats a database at this scale, and a read only UI cannot mutate the record it displays | A database for traces was deferred: JSONL plus the explorer covers the need, and the format keeps every published number auditable by eye | No key, no cost | IN USE NOW |
| Eval harness (own code) | Runs task suites through the runtime, scores mechanically from final state and trace assertions, writes the dated results files that are the repo's only source of numbers | Results that come from a harness can be rerun and checked; results typed into documents cannot | Model graded scoring for the core metrics was rejected: a task either did the thing or it did not, and citation correctness is checked against source records, not opinions | No key, no cost of its own (live model runs it drives do cost tokens) | IN USE NOW; the comparison extension is PLANNED FOR V2 Phase 5, framework in COMPARISON.md |
| Playwright with Chromium (headless shell) | The browser and computer use arm: drives real pages, grounds elements by role and accessible label (never CSS ids), verifies after every action, returns typed failures to the recovery engine | Real Chromium renders real JavaScript, which the work requires; semantic grounding survives layout shifts that break coordinate clicking, and fails classifiably when it cannot find a target | A DOM level fallback driver was scoped in Phase 2 and not needed once Playwright installed cleanly, so it was not built. Coordinate based clicking was rejected: it clicks the wrong thing silently instead of failing loudly | No key; free and open source; the Chromium build is a one time download (`playwright install chromium`) | IN USE NOW |

## Data sources and data libraries

| Name | What it does here | Why chosen | Rejected, and why | Key / cost | Status |
| --- | --- | --- | --- | --- | --- |
| PubMed via NCBI E-utilities (`src/aegis/data/pubmed.py`) | Literature retrieval: esearch turns a term into PubMed ids, efetch returns titles, abstracts, journal, and year, each record carrying its PubMed page URL | PubMed is the canonical public index for biomedical literature, the API is stable, documented, keyless, and returns the exact records citations will be checked against | Scraping PubMed web pages was rejected: fragile, against the spirit of a provided API, and it returns presentation markup instead of records. A third party literature API as the primary source was rejected: the citation checker must resolve against the source of truth, not a mirror | No key; free; anonymous rate limits apply and the client's two requests per search shape respects them | IN USE NOW (Tranche 1, with live smoke checks recorded in BUILD_JOURNAL.md) |
| ClinVar via NCBI E-utilities (`src/aegis/data/clinvar.py`) | Variant classification retrieval: esearch plus esummary return accession, HGVS title, germline classification, review status, and last evaluated date, each with its ClinVar variation page URL | ClinVar is the public archive of variant classifications and the ground truth source for the product's core questions and for comparison task design (reclassifications are dated, sourced events) | The ClinVar bulk FTP files as the primary path were rejected for the live layer: a product answering one question at a time should query the live record, with the cache providing reproducibility. Bulk data may still serve a future offline index, and would be labelled as such if it ever lands | No key; free | IN USE NOW (Tranche 1) |
| gnomAD via its GraphQL API (`src/aegis/data/gnomad.py`) | Population frequency lookup for one variant in a named dataset: genome and exome allele count, allele number, and allele frequency, with the variant's gnomAD page as the source URL | gnomAD is the reference population frequency source for variant interpretation, the GraphQL API answers one variant precisely, and naming the dataset in every record keeps frequencies honest across releases | Guessing frequencies from training data was rejected outright: a frequency is a number with a source or it is nothing. The older REST style endpoints were rejected: the GraphQL API is the supported public interface | No key; free; the API can be slow on cold queries, so this client carries a longer default time budget and a cache | IN USE NOW (Tranche 1) |
| AlphaMissense and REVEL scores via dbNSFP | Planned annotation source: precomputed pathogenicity scores for missense variants, of the kind the builder's evidence agent work already consults through dbNSFP style aggregated data | These scores are standard supporting evidence in variant interpretation, and they arrive as data with a provenance, not as model opinion | Claiming them as live API clients was rejected: dbNSFP is a distributed dataset, not a public API this repo can call today, so this row stays planned until the access path (licensed download or a hosted source) is actually in place and recorded | dbNSFP distribution has licence terms for some component scores; cost and terms to be recorded when the access path is chosen | PLANNED FOR V2 (Phase 2 extension; not in the product path yet) |
| Python standard library HTTP (urllib) | The transport for every API client and every model adapter in the repo | The wire formats are small and stable, zero new dependencies keeps local mode and tests hermetic, and the transport is injectable so tests replay recorded responses without network | Provider and API SDKs (anthropic, openai, requests, httpx) were rejected as the transport layer for now: each is one more dependency between the reader and the wire. An SDK can replace the transport later behind the same interface if a feature ever needs it, and the journal would record the change | No key, no cost | IN USE NOW |
| pytest | The test suite: unit, integration, and the end to end smoke tests, including the recorded fixture tests for the data layer | It is the standard Python test runner, it is already the repo's runner, and its fixtures (tmp_path, monkeypatch) are exactly what the cache and transport tests need | A second test framework for the data layer was rejected: one runner, one set of conventions | No key, no cost | IN USE NOW |
